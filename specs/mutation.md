# mutation

Problem: know which code no test covers and which tests prove nothing, without slowing every PR.

L1 PRs run only mutants in changed lines.
L2 One occasional full run on main, not on every push, and a push never cancels it.
L3 The full run reports and blocks nothing.
D1 PR gate: cargo mutants with --in-diff, in CI.
D2 Full run on a schedule, sharded, with no cancel-in-progress and shard limits long enough to finish.
D3 Full run records which tests kill which mutants: surviving mutants, tests that kill nothing, tests that fail where goldens do not. after: D2
D4 Incremental reruns (owner d2edfb63): a push to a PR mutates against the newest of its last ten completed ci runs that ran on an ancestor of the new head and left every shard's result (an artifact of the workflow, never local state); it mutates only that run's MISSED survivors, mapped to their current lines, and the PR-diff mutants on lines changed since the tree that run tested, plus every source line of a crate whose tests the PR first changed since then (a crate whose tests the earlier run's diff already changed was already mutated whole there, so adding to its tests selects only survivors and changed lines). A first run, a run with no complete prior on an ancestor (a force-push, a cancelled or partial run, expired artifacts), and a run whose own commits since the prior change test code in any way but pure additions fall back to a full run; test code is files under tests/, files holding #[cfg(test)], and crates that are only ever dev-dependencies, read from cargo metadata. A merge from main stays incremental: main's changes can un-exercise a PR mutant the prior run caught, and that gap is left to the widened sweep on main after merge (owner's "c" ruling). The merge gate is unchanged: every survivor must be killed and every changed line is mutated. Run cancelling stays as it is. A shard of an incremental run takes as its --in-diff a diff written from the selected mutants' own lines, found by listing the pull request's diff, because cargo-mutants 27.1.0 does not apply --re to struct-field deletions and every field deletion on a changed line would otherwise be tested again (D5). after: D1
D5 Hangs end: a PR or sweep mutation shard job stops at its planned time times 1.5, never below 45 minutes (owner bc45bff8; first a flat 45 minutes, owner 1092c4d5). mutants-plan predicts each shard's time as setup plus the cost of the mutants round-robin assigns it, each mutant costed at its crate's measured mean (build and test seconds from the branch's prior outcomes, divided by the two cargo-mutants jobs) or, for a crate with no measurement, 11 s, the rate observed on full-reach shards (the earlier flat 7 s cut four full-reach shards of #630 and #660 off at 54 to 68 minutes on 2026-11-18), and emits the cap with the shard, so a large shard is not cut off while a hang still ends; the cap stays within the hosted runner's 360-minute job limit. Every cargo-mutants run carries --build-timeout 600, so a mutant that hangs its build ends as TIMEOUT, excused like a test that hangs (D1), instead of holding the shard until the job dies. Every run also carries --timeout 120, three times the slowest measured test phase of a full-reach mutant (37 s, message-id, 2026-11-18), so a TIMEOUT means a hang: the timeout cargo-mutants otherwise sets from the baseline (20 s) sat at the length of an ordinary full-reach test phase, and survivors ended as TIMEOUT and were excused (export_mark in #655, three of #659's lowering mutants). A mutated build script can loop: in #622 Answered::next returning Some forever made design-messages' build script print without end and hung shard 8 for four hours. A test binary a mutant runs away in ends too: cargo-mutants' cargo test runs every test binary under prlimit, capping its private writable memory (RLIMIT_DATA, not address space, which thread stacks and allocator reservations inflate) at 6 GiB and its CPU at 300 seconds, about 20 and 30 times the largest measured on the Linux runner (295 MiB peak RSS, 9.1 s CPU), so a mutant that allocates or spins without bound fails its own test instead of starving the runner (lost runner on 2026-11-16, shard cancelled at the job limit on 2026-11-02). The scoped pass, which tests the own pass's survivors against every reached crate's tests, takes as its --in-diff a diff written from the survivors' own lines rather than the pull request's diff: cargo-mutants 27.1.0 applies --re to function mutants but not to struct-field deletions, so with the full diff each one-survivor scoped pass of #678 on 2026-11-25 also tested every changed field deletion (138 and 139 mutants, 33 minutes) and five of eight shards ran into the cap. after: D1
